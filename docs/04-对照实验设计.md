# 04 · 对照实验设计：多 Agent 到底带来了什么

这份文档回答一个问题：**"用多 Agent"这件事，除了架构图好看，有没有可测的收益？**

没有对照就没有答案。所以本项目把"多 Agent"当作**一个待检验的假设**，而不是前提。
下面写清实验怎么设、变量怎么控、指标怎么算、结论有多可信。

---

## 1. 三档配置（只有一个变量在动）

| 代号 | 配置 | 组成 | 用途 |
|---|---|---|---|
| **A** | 单 Agent 基线 | 一次检索 → 一次 LLM 生成（复刻 LawAnswer 现链路） | 对照物 |
| **B** | 多 Agent，无校验 | Triage → Statute / Calc 并行 → 一次 LLM 生成（校验器恒通过） | 隔离"编排"的收益 |
| **C** | 多 Agent + 五道闸 | B + G1~G5 + 引文对位 + 补检索回路 | 完整系统（强制全编排） |
| **D** | 成本感知路由 | 按风险选档：单跳走快速通道（1 次生成 + 4 道确定性闸），测算/多跳/合规走 C | 默认形态 |

**B 是这套实验的关键**。没有 B，只能得出"多 Agent + 校验整体更好"，
无法回答收益来自编排还是来自校验——而这两者的工程成本差一个数量级。
B 与 C 的拓扑完全相同，只把 `VerifierAgent` 换成恒通过的 `NullVerifierAgent`。

## 2. 控制变量

三档共用的东西（**都是刻意固定住的**）：

| 变量 | 取值 | 为什么必须固定 |
|---|---|---|
| 语料 | 1,465 条法条 / 2,935 块（劳动合同法 98 + 劳动法 107 + 民法典 1260） | 语料变了就没有可比性 |
| 检索器 | bge-m3 稠密，同一份 `dense.npy` 索引，top-k=5 | 否则差异可能来自检索而不是编排 |
| 生成模型 | `deepseek-v4.1-flash`，`enable_thinking=false`，temperature=0.1 | 同模型同参数 |
| 证据文本 | 父块整条（不是子块），预算 6,000 字符 | 喂给模型的东西一样 |
| 样本 | 法条问答 **100 条**（40 原始 + 60 生成）+ 金额测算 **30 条** | 同题同序；构建方法见 `docs/05`、`docs/06` |

**唯一允许不同的两处**（属于架构本身，不是放水）：

1. **B/C 会拆子查询**：多跳问题按 `sub_queries` 分路检索，A 只检索一次。
   这是多 Agent 的机制之一，不固定它等于把假设的前提拿掉。
2. **B/C 的金额由确定性引擎算**，A 由模型心算。这正是要被检验的差异。

> A 档不是稻草人：它拿到的是 B/C 第一跳检索到的同一批条文，Prompt 里也明确要求
> "只能引用资料中的条文""不得编造条号""未覆盖就写未覆盖"。

## 3. 指标定义（五列确定性 + 一列模型判定）

| 列 | 定义 | 是否依赖模型 |
|---|---|---|
| **Recall@5** | 检索结果按分数排序取前 5，命中期望法条的比例（条级，`法名#条号` 唯一标识） | 否 |
| **引注有效率** | 答案里的 `《法》第X条` 中，条号在语料中**真实存在**的比例（简称自动对齐全称） | 否 |
| **引注可溯率** | 引用的条号属于**本次检索到的证据**的比例（衡量"是不是凭记忆写的"） | 否 |
| **引用命中率** | 期望法条被答案**引用**的比例（不是被检索到，是被写进答案） | 否 |
| **金额准确率** | 与金标金额误差 ≤ 1 元（测算集 9 题） | 否 |
| **LLM 调用数** | 每题的模型调用次数（含分诊、撰稿、G4、回路） | 否 |
| **P95 延迟** | 端到端耗时的 95 分位 | 否 |
| **支撑率**（faithfulness） | 断言级：1 − 无依据断言数 / 断言总数 | **是**（同族模型判定） |

**为什么把"引用准确率"拆成三列**：LawAnswer 原来只有一个"引用命中率 81.8%"，
是人工统计、口径模糊、不含误报。拆开之后，"编造条号""凭记忆引用""引用对了但没答到点上"
这三种完全不同的错误才分别可见——而这三种的技术对策完全不同。

## 4. 已知的威胁（必须写出来，否则数字站不住）

1. **支撑率由同一族模型判定**。C 档的答案本就经过 G4 约束，用同族模型再判一次，
   天然有利于 C。因此这一列只在三档之间**横向比较**，绝对值不可跨系统引用。
2. **样本量 100+30**。法条题 100 条（单配置区间约 ±8pt，差异用配对 bootstrap）；
   金额题 30 条，单题权重 3.3%，57pt 的差距区间不重叠，**可以当结论读**。
3. **A 档的知识被限制在检索结果内**。真实产品里的单 Agent 往往可以联网或凭参数记忆，
   这里刻意不给，是为了让"证据来源"这个变量可控。代价是 A 档可能被低估。
4. **题目分布偏劳动法**（40 题里 34 题），民法典题只有 6 题，分法域结论不可靠。

## 5. 复现方式

```bash
python -m eval.compare_agents --limit 8            # 小样本验链路（约 1 分钟）
python -m eval.compare_agents --faithfulness       # 全量 + 支撑率（约 11 分钟）
python -m eval.compare_stats                       # 配对区间（零调用）
python -m eval.compare_agents --reuse              # 复用已跑样本，只重算汇总
```

原始输出落 `eval/results/raw/{law,calc}_{config}.jsonl`，逐题含全文、证据、裁决、耗时。
汇总落 `eval/results/compare_report.json`，**按段合并**：只重跑 `--set calc` 时 `law` 段原样保留，
每段带自己的 `generated_at` 与样本量——否则局部重跑会让报告看起来"退步了"。
任何一次报告都能追到具体某一题的原文——这一点比数字本身更重要。

## 6. 结果

结果与解读写在 `REPORT.md` §9（表 4 / 表 5）。一句话结论：

> 多 Agent 的收益集中在**可计算**（金额 66.7% → 100%）与**可核验**（引注可溯 98.3% → 100%、
> R@5 0.741 → 0.807）两处，代价是 3.6 倍调用与 3 倍延迟；
> 单跳规则问答用它不划算。所以它应该是"高风险问题的增强路径"，而不是默认形态。

本文件只负责说明"怎么测的、测的是什么、哪里不可信"。
