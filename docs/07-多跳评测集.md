# 07 · 多跳评测集是怎么补的（100 → 130 条）

100 条集里多跳 12 条、复杂 8 条，**复杂题只有 8 条**。"复杂题 +19pt"这种结论就架在这 8 条上，
95% 区间宽到 ±20pt，等于用噪声讲故事。阶段 7 的目标很直接：把多跳/复杂样本补到 ≥50 条，
然后**看原来的结论还站不站得住**——如果不站，就写"不成立"。

结论先说：**不成立**（详见 `REPORT.md` §9.4）。这份文档记录这 30 条是怎么来的、哪里可能有偏。

## 1. 为什么不能沿用单条出题

`eval/gen_qa_set.py` 是"给一条法条 → 让模型写问题 → 答案就是这条法条"，金标由构造保证。
多跳题的金标是**几条法条的组合**，这个组合不能让模型自由发挥：模型多写或少写一条，
金标就错了，而且**错了也看不出来**（指标只会静默偏低）。

所以流程反过来：**条号组合由人指定，模型只负责把组合写成一个当事人会问的问题。**

## 2. 生成流程（`eval/gen_multihop.py`）

```
人工指定 48 组条号组合（2–3 条，劳动法/劳动合同法/民法典）
   ↓
LLM 写口语问题 + 每条法条对应的子问题（禁止条号/法名/书名号，禁止照抄原文）
   ↓
过滤 1：题面与组合内全部原文的字符二元组重合率 > 0.45 直接丢弃
过滤 2：与已有 100 题任一题面的 Jaccard > 0.70 直接丢弃（档"换个说法重复出题"）
   ↓
第二次 LLM 调用：逐条问"去掉这一条，这个问题还能完整回答吗"
   → needed ≥ 2 且 sufficient 才通过；否则整条丢弃
   ↓
入库（eval/generated/multihop_candidates.jsonl，40 条）
   ↓
人工复核条组合 + 按法域配额取 30 条（eval/build_set_130.py → eval/qa_set_130.jsonl）
```

三道过滤各挡一类偏差：

| 偏差 | 为什么致命 | 挡法 |
|---|---|---|
| **题面泄漏原文** | 检索退化成词组匹配，四档一起虚高 | 重合率 > 0.45 丢弃；本次通过项中位 0.13、最大 0.286 |
| **题面与旧题重复** | 同一道题被算两次，区间虚窄 | 与 100 题题面 Jaccard > 0.70 丢弃；本次最大 0.273 |
| **组合不是"都必须"** | 多写了条号 = 金标错误，系统被冤枉 | 逐条必要性校验，needed < 2 整条丢弃 |

## 3. 30 条怎么选出来的

* **候选 40 条**（48 组里通过 40 组，通过率 83%）：其中 calc 5 条、reason 35 条；
* **人工剔除 3 条**：题面问的规则超出所给法条，金标不完整。剔除记录写在
  `eval/build_set_130.py` 的 `EXCLUDED_TOPICS`，不静默丢弃：

| 被剔除的主题 | 原因 |
|---|---|
| 劳务派遣员工被退回后能否解除 | 题面问"能不能随时走人"，需要第三十七条，组合里没给 |
| 离职时工资与手续怎么结 | 题面问"能马上要补偿吗"，需要第四十六条，组合里没给 |
| 招用未解除合同员工的连带责任 | 题面是包工头场景，需要第九十四条；给的第九十一条不对题 |

* **配额取 30 条**：calc 类全部收（5 条）→ `complex`；其余按 **劳动 17 / 民事 8** 取
  → `multi_hop`。按法域配额而不是按文件顺序截断，是为了不让民事题被整段切掉。
  最终 5 条 `complex` 全部来自 calc（金标 3 条 + 具体金额），25 条 `multi_hop` 中劳动 17、民事 8。

## 5. 必须写出来的五个偏差

**① 金标的正确性来源变了。** 100 条集的金标"由构造保证"（答案是抽样得到的法条本身）；
130 条的新增 30 条是**人工指定组合 + 机器校验必要性**。机器只判"这几条是否都必须"，
不判"这个组合在法律上是否恰好够用"——后者靠人。所以新增题的金标强度**低于**前 100 条，
`gold_review` 字段如实记成 `necessity_checked+manual_combo`，与 100 条集的生成题不是同一口径。

**② 出题模型知道金标（与 100 条集同病）。** 模型看着法条写问题，问法天然贴合法条的语义中心，
绝对分数会偏乐观；但四档吃的是同一批题，**配对差异仍然有效**——这正是配对设计的价值。

**③ 配额是人为的，不是抽样。** 劳动 17 / 民事 8 是为了保住民事法域，不代表两类题在法律实务中的比例。
所以这 30 条**不能**用来推断"劳动题 vs 民事题谁更难"。

**④ 5 条复杂题只测定性，不测金额。** 它们都带固定事实（`2021-03-01 入职、2026-10-20 离职、月薪 12000`），
但法条集（`--set law`）只算 R@5 / 引用命中 / 引注有效可溯，**不算金额准确率**。
金额能力看 `eval/calc_cases.jsonl`（§9.2），两套评测不混用。

**⑤ 复杂题即使扩到 13 条，仍然测不出东西。** n=13 时引用命中的 95% 区间约 ±17pt，
C−A 是 +1.3pt、区间 [−0.160, +0.173]。**样本量不够就是不够**，不能拿点估计当结论。
多跳题 n=37 同样测不出 C−A 的 +6.8pt（区间 [−0.041, +0.162]）——
可区分的只有拓扑相同、只差校验器的 C−B。

## 6. 结果与复现

结果见 `REPORT.md` §9.4（130 条四档表、分题型区间、以及"复杂题 +19pt 不成立"的自我更正）。

```bash
# 1) 生成候选（48 组，约 60 次调用；--only 可按主题补跑，产物按主题合并）
python -m eval.gen_multihop --concurrency 4

# 2) 合成 130 条（零调用，幂等）
python -m eval.build_set_130

# 3) 四档跑新增 30 题（--reuse 复用已有 100 题的原始输出，只跑缺的样本）
python -m eval.compare_agents --law-set eval/qa_set_130.jsonl --reuse

# 4) 带区间与分题型的统计（零调用）
python -m eval.compare_stats --samples eval/qa_set_130.jsonl --set law
```

生成结果取决于模型措辞（LLM 生成有波动），但**题号、组合、金标条号**由 `COMBOS` 与
`build_set_130.py` 的配额决定，可复现。原始逐题输出在 `eval/results/raw/law_*.jsonl`，
任何一行数字都能追到那道题的答案原文。
