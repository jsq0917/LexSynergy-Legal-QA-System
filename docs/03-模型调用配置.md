# 模型调用配置（阿里云百炼 / DashScope）

> 日期：2026-10-28
> 本文记录**实际测过**的端点、参数与坑，不是照文档抄的。所有结论都能用 `scripts/check_llm.py` 复现。

---

## 1. 模型分工

| 用途 | 模型 | 位置 | 说明 |
|---|---|---|---|
| 文本生成（Triage / 撰稿 / G4 支撑判定） | **`deepseek-v4.1-flash`** | 阿里云百炼 | 统一使用，不混用其他生成模型 |
| 稠密检索（默认） | **bge-m3**（1024 维） | 本地 | 已建索引（`data/corpus/dense.npy`），零成本、可离线复现 |
| 稠密检索（备选，无 torch 环境） | **`qwen3.7-text-embedding-flash`**（1024 维） | 百炼 | 需重建索引；见 §6 |
| 重排 | bge-reranker-v2-m3 | 本地 | 权重已在 `models/`；百炼兼容模式未暴露 rerank 端点（`/reranks` → 404） |

**为什么检索不用云端 embedding**：现有索引是 bge-m3 建的，R@5 0.7381 也是在这个索引上测的。
换 embedding 等于换向量空间，必须重建全量索引、重测所有指标 —— 收益不明确，代价是模型可复现性。
云端 embedding 只作为「部署环境没有 torch」时的备选，并明确标注需要重建索引。

## 2. 端点与鉴权

```
Base URL : https://dashscope.aliyuncs.com/compatible-mode/v1
鉴权     : Authorization: Bearer <API_KEY>
路径     : POST /chat/completions     ← 文本生成
           POST /embeddings           ← 向量
           GET  /models               ← 列可用模型（实测返回 183 个）
```

OpenAI 兼容模式，所以任何 OpenAI SDK 都能直接接；本项目用 `httpx` 直连，少一层依赖。

**Key 的存放**（按优先级）：

| 顺序 | 位置 | 用途 |
|---|---|---|
| 1 | 进程环境变量 `LLM_API_KEY` | CI / 容器 / 生产 |
| 2 | 项目根 `.env`（已 gitignore） | 本地开发 |
| 3 | 代码默认值（空） | 无 |

`config.load_dotenv()` **不会覆盖**已存在的环境变量，所以 `export LLM_API_KEY=...` 永远压过 `.env`，
避免本地文件误覆盖生产 key。

## 3. 请求参数（本项目实际发送的）

```json
{
  "model": "deepseek-v4.1-flash",
  "messages": [{"role": "system", "content": "..."}, {"role": "user", "content": "..."}],
  "temperature": 0.1,
  "max_tokens": 1600,
  "enable_thinking": false,
  "response_format": {"type": "json_object"}
}
```

| 参数 | 取值 | 为什么 |
|---|---|---|
| `temperature` | 0.1（生成）/ 0（判卷） | 法律场景要稳定，不要发挥 |
| `max_tokens` | 1600（撰稿）/ 400-600（Triage、G4） | 按任务切；注意思考模式会吃额度 |
| `enable_thinking` | **`false`** | 见坑 ①：不关会返回空 content |
| `response_format` | 仅 JSON 任务用 `json_object` | 见坑 ③：仍要自己校验 |
| `stream_options` | **只在 `stream=true` 时带** | 见坑 ②：非流式带上直接 400 |

## 4. 六个实测踩到的坑（按踩坑顺序）

### ① 思考模式会让 content 返回空

`deepseek-v4.1-flash` **默认开启思考**。`max_tokens=16` 时，16 个 token 全进了 `reasoning_content`，
`content` 为空、`finish_reason=length` —— 代码会以为模型什么都没说。

| 请求 | completion_tokens | content | reasoning |
|---|---|---|---|
| `max_tokens=16`（默认思考） | 16 | **空** | 16 |
| `max_tokens=64`（默认思考） | 33 | `可用` | 95 字 |
| **`enable_thinking=false`** | **2** | `可用` | 0 |

→ 每个请求显式带 `enable_thinking: false`。同样的问题从 33 个 token 降到 2 个，延迟也降。
（`thinking: {"type":"disabled"}` 与 `reasoning_effort: "none"` 也生效，但 `enable_thinking` 是本平台原生字段。）

### ② `stream_options` 必须和 `stream` 成对出现

非流式请求里带 `stream_options` 会被 400：

```
{"error":{"message":"'stream' and 'stream_options' must be set together as explicitly required."}}
```

→ 只在 `chat_stream()` 里同时设置 `stream: true` + `stream_options: {include_usage: true}`。

### ③ JSON 模式不保证 schema

`response_format={"type":"json_object"}` 能返回合法 JSON，但实测出现过**键名被改写**：
要求输出 `{"intent": ...}`，返回 `{"int#": ...}`。

→ 所以 `json_chat()` 只负责「拿到 dict」，字段合法性由调用方逐个校验（`LLMTriager._merge`），
非法值一律回落到规则结果。**不能假设 JSON 模式等于结构化输出。**

### ④ embedding 模型要选对，且注意额度

| 模型 | 结果 |
|---|---|
| `text-embedding-v3` / `v4` | 400 `Free quota exhausted` |
| `qwen3.7-text-embedding` | 400 `Free quota exhausted` |
| **`qwen3.7-text-embedding-flash`** | ✅ 可用，1024 维（与现有索引同维） |

→ 云端 embedding 指定 `qwen3.7-text-embedding-flash`。同维只是巧合，**向量不可互换**。

### ⑤ 模型名是别名，实际路由到带日期的版本

`/models` 里同时存在 `deepseek-v4.1-flash`、`deepseek-v4.1-flash-1017`、`vanchin/deepseek-v4.1-flash`。
请求 `deepseek-v4.1-flash` 可用，响应 `model` 字段回显该名。**升级前先跑回归**（`scripts/check_llm.py`），
不要假设别名永远指向同一版本。

### ⑥ 延迟：首 token 慢，且不要在请求路径里加载模型

实测（单次、无并发）：

| 环节 | 耗时 | 备注 |
|---|---|---|
| Triage（in=585 / out=94） | **1.7s** | 含网络往返 |
| 撰稿（in=901 / out=517） | **3.7s** | 600 字答案 |
| G4 支撑判定（~8 条断言） | **2-4s** | 与断言条数正相关 |
| bge-m3 冷启动 | **13s** | **进程级一次性**，不是每次请求 |

→ bge-m3 懒加载 + 进程内常驻；`as_of`/`temperature` 固定，避免抖动。
端到端首次 ~19s、二次 ~6s（模型已驻留）。

## 5. 调用路径与次数

```
Pipeline.run
  ├─ LLMTriager        → 1 次 chat（JSON 模式，max_tokens=400，fast_model）
  ├─ Scheduler         → 0 次（Statute/Calc 都不含 LLM）
  ├─ LLMSynthesizer    → 1 次 chat（max_tokens=1200）
  └─ VerifierAgent
       ├─ G1/G2/G3/G5  → 0 次（纯代码）
       └─ G4            → 1 次 chat（JSON 模式，max_tokens=600）
```

* 正常路径 **3 次** LLM；
* 校验不过触发补检索回路时 **4 次**（回路硬上限 1 次）；
* `--no-llm` 时 **0 次**（规则 Triage + 模板撰稿，用于离线测试与成本对照）。

## 6. 切换到其他模型 / 云端 embedding

**换生成模型**：只改 `.env`

```bash
LLM_MODEL=deepseek-v4.1-flash      # 换名字即可，代码不动
LLM_MODEL_FAST=                    # 留空 = 复用 LLM_MODEL
```

**换云端 embedding**（需要重建索引）：

```bash
EMBEDDING_BACKEND=dashscope
EMBEDDING_DASHSCOPE_MODEL=qwen3.7-text-embedding-flash
python -m scripts.build_embeddings --backend dashscope   # 重建 dense.npy
python -m eval.recall_eval --ablate                      # 重测，确认没退化再上线
```

> ⚠️ 换 embedding 后 **必须重测**：向量空间变了，旧的 R@5 0.7381 不再成立。
> 本项目默认不换，就是为了保住可复现的评测基线。

## 7. 降级矩阵（任何一环坏掉都不空答）

| 故障 | 表现 | 降级 |
|---|---|---|
| Key 无效 / 无权 | 401 / 403 | Triage→规则；撰稿→模板；G4→skipped |
| 额度耗尽 | 400 `quota` | 同上，并在日志里明确报 `LLMQuotaError` |
| 限流 | 429 | 指数退避重试 2 次，仍失败则降级 |
| 超时 | 60s | 同上 |
| 空 content（思考模式没关） | `finish_reason=length` | 抛 `LLMResponseError` → 降级 + 告警 |
| JSON 不合法 | 解析失败 | Triage→规则；G4→skipped |
| embedding 模型缺 | 建索引失败 | 检索回退 BM25（R@5 0.5857） |

## 8. 自检脚本

```bash
python -m scripts.check_llm
```

会依次验证：Key 是否有效 → `/models` 是否可达 → 非流式 chat 是否返回非空 → JSON 模式是否可用
→ embedding 是否可用（仅提示）→ 打印 token 用量与延迟。**换模型/换 Key 后先跑它。**
