# 08 · 支撑率评测（独立 judge）

> 对应阶段 9。脚本：`eval/faithfulness.py`；结果：`eval/results/faithfulness.json`。
> 目的只有一个：把 REPORT 里那一列**长期标 ⚠ 的支撑率**变成"可复现、能引用"。
> 结论见第四节；如果你只想知道"能不能引"，直接看第五节。

## 一、为什么旧口径不能用

旧列来自 `python -m eval.compare_agents --faithfulness`。它有三个结构性缺陷：

| 缺陷 | 具体表现 | 后果 |
|---|---|---|
| **判官与被判同族** | 答案由 `deepseek-v4.1-flash` 生成，判官也是它 | 同源偏见互相认可，"错得一致"测不出来 |
| **参数未钉死** | 走全局默认 `temperature=0.1`，Prompt 无版本号 | 同一答案重跑漂移 **±0.02**，改 Prompt 后历史数字不可比 |
| **只测一次** | 没有重复测量 | 无法区分"配置差异"与"采样噪声" |

所以 REPORT §9 的支撑率一直是"仅列示、不作结论"。这一阶段不动答案、不动检索、
不动编排，**只换判官与测量方式**。

## 二、方法与参数

| 项 | 取值 | 理由 |
|---|---|---|
| 判官模型 | `qwen3.8-27b` | 非 deepseek 族；实测 3.7 系免费额度已耗尽（403） |
| `temperature` | **0**（在代码里硬编码，不读全局默认值） | 同输入必须同输出 |
| `enable_thinking` | `false` | 与主链路一致；避免 reasoning 吃光 `max_tokens` |
| Prompt | `faith-v1.0`，版本号写在 system 里 | 改一个字的措辞都必须升版本 |
| 重复次数 | 3 | 验收要求：3 次漂移 <0.01 |
| 输入 | 已落盘的原始输出 `eval/results/raw/law_*.jsonl` | **判官不改答案**，只重判同一批文本 |

评分口径（断言级，与 G4 同一套切分 `verifier.gates.claims_of`）：

```
支撑率 = 1 - 匹配到断言上的"无依据断言"数 / 断言总数
```

两个细节：

1. **stray 不计入分子**：判官偶尔把纯引文、过渡句、免责声明列回来，那是 Prompt 偏差，
   不是答案的错。这些条目单独记在 `stray` 里供审计。
2. **匹配用三级**：归一化包含 → 相似度（≥0.6）。判官常把断言截短或改标点，
   全等匹配会把 1 条错算成 2 条。

漂移定义：**所有配置上、任意两次之间支撑率差的最大值**（不是标准差）。
验收阈值 `DRIFT_LIMIT = 0.01`。

## 三、结果

130 条 × 4 配置 = 520 份答案，同一批文本判 3 次（共 1,560 次调用，约 3.9 分钟）：

| 配置 | 第 1 次 | 第 2 次 | 第 3 次 | 均值 | 组内漂移 |
|---|---|---|---|---|---|
| A_baseline（单 Agent） | 0.9226 | 0.9249 | 0.9277 | **0.9251** | 0.0051 |
| B_multi（多 Agent，无校验） | 0.9308 | 0.9304 | 0.9292 | **0.9301** | 0.0016 |
| C_verified（多 Agent + 五道闸） | 0.9566 | 0.9515 | 0.9535 | **0.9539** | 0.0051 |
| D_auto（成本感知路由） | 0.9448 | 0.9479 | 0.9495 | **0.9474** | 0.0047 |

* **最大漂移 0.0051（A_baseline）< 0.01 → 验收通过。**
* 判官失败 3/1,560（每次各 1 题：答案里没有可判断言，`no_claims`），未进均值。
* 四个配置的**排序在 3 次里完全一致**：C > D > B > A。

与旧口径（同族 judge、100 条、单次）对比：

| 配置 | 旧口径（⚠ 不可引用） | 新口径（可引用） |
|---|---|---|
| A | 0.932 | 0.925 |
| B | 0.856 | 0.930 |
| C | 0.866 | 0.954 |
| D | 0.882 | 0.947 |

**排序被整个翻过来了**（旧：A 最高、B 最低；新：C 最高、A 最低）。
这不是"新判官更准"就能解释的，更可能的解释是旧口径确实被同源偏见与单次采样带偏了：
旧判官倾向于放过与它自己写法相近的答案（A 是同一模型的自由格式输出）。

## 四、这张表能说什么

**能说**：

1. 同批答案下，C（带校验）比 A（单 Agent）高 **2.9pt**，且三次重跑的差值分别是
   +0.034 / +0.027 / +0.026 —— **方向稳定，量级高于测量漂移（0.005）**；
2. 校验器这一层是支撑率的来源：C 相对 B（同拓扑、只差校验）高 **2.4pt**（+0.026 / +0.021 / +0.024，同样三次同号）；
3. 这一列现在是**可复现的**：给同一批答案、同一个判官、同一个 Prompt 版本，任何人重跑都应落在 ±0.005 内。

**不能说**：

1. **绝对值的跨系统比较**：0.954 只在这个判官 + 这个 Prompt 下成立，换个判官会变；
2. **"答案 95% 被支撑"这种表述**：判官仍有错判，本阶段证明的是"可复现"，不是"判官正确"；
3. **统计显著性**：本阶段没做配对 bootstrap（逐题分数未落盘），
   2.9pt / 2.4pt 只能说"方向稳定、高于漂移"，不能说"区间不含 0"；
4. **B 与 A 的 0.5pt 差距**：与组内漂移同量级，**不可区分**。

## 五、能不能引用

**可以引用了**，但必须带三件限定：`qwen3.8-27b`、`faith-v1.0`、3 次重跑漂移 0.0051。

推荐写法：

> "支撑率由独立判官（qwen3.8-27b，temperature=0，固定 Prompt 版本）判定，
> 同一批 130 条 × 4 配置重跑 3 次，最大漂移 0.0051；带校验的配置 0.954，
> 单 Agent 0.925，差值 2.9pt 在三次重跑中方向一致。"

**不要**写"支撑率 95.4%，说明回答基本都有依据"——判官正确率没测过，这句撑不住。

## 六、复现与坑

```bash
# 全量（130 条 × 4 配置 × 3 次 ≈ 1,560 次判官调用，约 10 分钟）
python -m eval.faithfulness --repeats 3 --concurrency 10

# 小样本验链路
python -m eval.faithfulness --limit 2 --repeats 1

# 只检查 Prompt（零调用）
python -m eval.faithfulness --dry-run
```

三个已经踩过的坑：

1. **`qwen3.7-plus` / `qwen3.7-flash` 返回 403 "Free quota exhausted"**。
   换 `qwen3.8-27b`（或 `qwen3.8-flash`）可用。换模型必须同时记录在结果 JSON 里，
   否则不同判官下的支撑率不能放一张表。
2. **判官全挂时漂移是 0.0000**。每次都是 NaN，差值自然是 0 —— 差一点就"通过"了。
   现在 `report()` 先查覆盖率（失败率 >10% 或有效轮次 <2 → 判 `insufficient`），有单测钉住。
3. **答案里没有可判断言**（纯模板、纯引文）会返回 `no_claims`，算失败但不调用判官。
   这类样本不进均值，也不该被当成"支撑率 1.0"。
