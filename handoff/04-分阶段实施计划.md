### 阶段 8 · 撰稿流式化 ✅ **已完成（2026-10-28）**

| 项 | 内容 |
|---|---|
| 目标 | 首字延迟从 ~3s 降到 <1s（**体感，不是总时长**） |
| 任务 | `LLMSynthesizer` 增加 `stream()`（`chat_stream()` + 线程安全队列），`delta` 事件分片下发 |
| 影响面 | `app/generation/{synthesizer,llm_client}.py`、`app/orchestrator/pipeline.py`、`web/{app.js,style.css}`、`eval/latency_probe.py` |
| 风险处理 | 无法"生成后校验再拦" → 先流式呈现，终稿 `delta` 用校验后的完整文本**整体替换**；未过闸时告示前置到答案顶部，前端 `passed=false` 标红 |
| 交付物 | 流式撰稿 + `tests/test_stream_synth.py`（9 条，零网络） |
| 验收结果 | 快速通道首字 P50 **753ms** / P95 **798ms**；撰稿首字 P50 612ms；全编排请求级首字 P50 3.4s（瓶颈是 LLM 分诊，不是撰稿）；未过闸真实验收 `passed=false` 且横幅在顶部 ✅ |

**遗留边界（如实记录）**：全编排的**请求级**首字仍 >1s —— LLM 分诊 P50 2.3s，
是当前唯一体感瓶颈；撰稿本身（P50 676ms）已达标。要么走快速通道，要么下一步给分诊做缓存/小模型。
