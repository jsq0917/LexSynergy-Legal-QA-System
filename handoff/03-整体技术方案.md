# 03 · 整体技术方案

## 一、五层架构

```
接入层   FastAPI :8201  ─ GET /  静态页 · POST /api/chat · POST /api/chat/stream(SSE)
   │
编排层   Pipeline  ─ Triage(规则/LLM) → 定档(auto/fast/full) → Planner → Scheduler(DAG)
   │                   → Synthesize → Verify(五道闸) → 回路(≤1次) → 交付
   │
专家层   Statute(无LLM) · Calc(无LLM) · Compliance(LLM) · Verifier(规则+LLM)
   │       ↑ 四个都可经 A2A 独立部署，业务逻辑不依赖协议
   │
协议层   protocol/executor(≈40行) · invoker(inproc|http) · server
   │
数据层   真实语料 1,465 条 / 2,935 块 · dense.npy(bge-m3 1024维) · BM25 索引
```

**关键设计**：业务逻辑写在 `Agent.run(payload)` 里，协议适配写在 `protocol/executor.py` 里。
这条分界让单测可以完全绕过 A2A（不启容器、不构造 `RequestContext`）。

## 二、四个专家的职责边界

| 专家 | 输入 | 输出（artifact） | 含 LLM | 关键约束 |
|---|---|---|---|---|
| **Statute** | `sub_query` + `law_hints` + `query` | `{count, queries}` + Evidence[] | ❌ | **只交证据、不写结论**；永远不编故事 |
| **Calc** | `kinds` + 结构化 `facts` | `{results: [{kind, formula, substitution, value, unit, basis_articles, assumptions}]}` | ❌ | **只接受结构化参数**，不接受自然语言；缺槽位抛 `MissingSlots` |
| **Compliance** | `text` + `role` + `context`(证据) | `{issues: [...]}` | ✅ | 企业方视角触发 |
| **Verifier** | `draft` + `evidence` + `calc_values` + `extra_context` | `Verdict{passed, action, checked, fails, skipped_gates}` | 部分 | **只判法律命题**，不复判事实与算术 |

### 为什么 Calc 无 LLM 也算 Agent

判据是"能力边界 + 可独立部署 + 稳定契约"，不是"有没有大模型"。
它只做一件确定的事，因此**永远不会算错**（算错只可能是公式写错，那是可测的）。

### 五道闸与三态裁决

| 闸 | 抓什么 | LLM | 实现要点 |
|---|---|---|---|
| G1 | 编造引用 / 张冠李戴 / 跨法拼接 | ❌ | 账本 `lookup()` 含**法名简称解析**（`《劳动合同法》` → 全称） |
| G2 | 篡改引文 | ❌ | 归一化后必须是原文**连续片段**；允许 `……` 分段，每段按顺序出现 |
| G3 | 引用已废止版本 | ❌ | `effective_at(as_of)` |
| G4 | 引对了条文但支撑不了结论（Mode 2，最危险） | ✅ | 断言级判定；**只判法律命题**，复述事实/结果不判 |
| G5 | 算错金额 | ❌ | 合法金额 = 最终值 + **公式中间量**（否则"57.47 元/小时"会被判编造） |

**裁决三态**：`pass` / `refine_retrieval`（补检索）/ `downgrade`（金额错标红不改写）。

**三类失败三种修法**（这是实测调出来的，不是设计的）：

| 失败 | 修法 | 成本 |
|---|---|---|
| G1 引用了没检索到的条号 | 补检索 → **复查原稿**（多半不用重写） | 0 次 LLM |
| G2 引文对、条号错 | **引文自动对位**（改标签不改文字） | 0 次 LLM |
| G4 断言无依据 | 重写 | 2 次 LLM |

**回路硬上限 1 次**，防死循环。

### 引文自动对位（`app/verifier/repair.py`）

模型最常见的错误不是编造，而是**错位一格**（把第四十七条原文挂到第四十六条上）。
这类答案每个字都是真的，G2 只能判失败然后走回路（多烧 2 次 LLM），但问题其实出在标签。

修复是确定性的：引文若逐字命中账本里另一条证据，就改标签。三条保守约束：
1. 引文为空 → 不修；2. 原文里该引用串出现多次 → 不修；3. 命中不止一条 → 不修。
**最后一道保险**：改完必须让冲突数严格下降，否则整体退回原文。

## 三、成本感知路由（`app/orchestrator/routing.py`）

**背景**：全编排在单跳规则问答上只多 3pt 引用命中，却贵 3.6 倍、慢 3 倍。

| 判据（全部零 LLM） | 档位 |
|---|---|
| 金钱类测算（severance/illegal/notice/overtime/double_wage/annual_leave/non_compete） | `full` |
| 多跳（计划里 ≥2 路检索） | `full` |
| 合规审查（企业方 / 制度条款） | `full` |
| 其余 | `fast` |

`fast` 不等于不校验：**不调 LLM 分诊、不跑 G4、无回路**，但 **G1/G2/G3/G5 + 引文对位照跑**。

**顺序不能反**：若先用 LLM 分诊再决定走不走廉价通道，省下的钱又被分诊吃回去。
所以：`规则分诊 → 定档 → fast 直接用规则结果；full 才调 LLM 分诊`。

**关键陷阱（已踩过一次）**：档位判定用**宽口径**（`needs_calc` 有任何金钱类 kind 就升级），
算不算得成由全编排里的严格规则再定。否则会死循环：
不算钱 → 走 fast → 不调 LLM 分诊 → 永远抽不到槽 → 永远不算钱。

`ROUTING_POLICY=auto|fast|full`，CLI `--policy` 可单次覆盖。详见 `docs/adr/0002-cost-aware-routing.md`。

## 四、时间预算（三道闸，别搞混）

| 配置 | 作用域 | 默认 |
|---|---|---|
| `budget.step_timeout_s` | **单个 agent 步** | 20s |
| `budget.deadline_s` | **整个 DAG** | 25s |
| `request_deadline_s` | **整个请求**（含撰稿/校验/回路） | 45s |

**为什么需要第三道**：前两道只罩住 DAG，撰稿、G4、回路都在它们外面。
不设第三道，一次 LLM 超时就能把请求拖到 70s（实测过）。

**实现必须用 `asyncio.wait_for`**，不能只在每步开始前查 `ctx.expired()` ——
后者对**正在飞**的调用无能为力（实测 deadline=2s、撰稿 8s，端到端仍 8.0s）。

超时后的去向：**模板撰稿 + 确定性四道闸 + `degraded="timeout"`**，答案完整不截断。

## 五、SSE 事件契约（前端与评测共用）

```
meta    → {intent, role, complexity, route, mode, reasons, plan_fingerprint}
plan    → {reason, steps:[{id, agent, deps, status}], fingerprint}
agent   → {step_id, agent, status, elapsed_ms, evidence, llm_calls, error}   × N
sources → {sources:[{eid, law, article_no, quote, score, ...}]}
verify  → {passed, action, checked, fails, skipped_gates, repaired?, no_rewrite?, timeout?}
delta   → {text}
done    → {latency_ms, llm_calls, timings:{triage_ms,dag_ms,synth_ms,verify_ms,loops}, mode, degraded}
```

**必须保证**：`done` 或 `error` 一定出现（否则前端永远转圈）。有测试盯住。

## 六、降级矩阵（每一处坏了都不该断链）

| 故障 | 降级 |
|---|---|
| LLM 分诊失败 | 回落规则分诊（逐字段回落，不是整条作废） |
| LLM 撰稿失败/超时 | 退回模板撰稿器 |
| G4 judge 失败 | 标 `skipped`，其余四道闸照跑 |
| 稠密索引缺失 | 退回 BM25 |
| 语料缺失 | 退回 10 条演示语料 |
| 检索整段超时 | **明说"检索没能完成"**，绝不说"没有相关规定" |
| 请求超时 | 模板答案 + `degraded="timeout"` |

## 七、缓存键

`ans:{query_hash}:{role}:{plan_fingerprint}:{as_of}:{mode}`

**mode 必须进键**：同一个单跳问题，fast（无 G4、无回路）与 full（五道闸）产物不同，
共用键会让后一次读到前一次的裁决。
