# 09 · 工作边界与注意事项

## 一、你的权限范围

### ✅ 可以自主做

- 新增/修改**实现代码**（`app/`）与**测试**（`tests/`），只要是阶段计划内的
- 新增**评测脚本**与样本集（`eval/`），但金标必须可核对
- 修 bug、补注释、加回归测试
- 更新 `docs/` 与 `handoff/` 文档
- 优化性能（但必须给前后对比）

### ⚠️ 需要先说明再做

- 改动**已验收的数字**（`README.md` / `REPORT.md` 里的指标）
- 改动**五道闸判定逻辑**、**金额公式**、**路由判据**
- 引入**新依赖**（尤其是会拉起大模型的）
- 改动 `config.py` 的默认值
- 重构跨 3 个以上模块的代码

### ❌ 不要做

- 删除或改写 `eval/qa_test_cases.jsonl`（历史数字的来源）
- 升级 `a2a-sdk`（除非完整跑通 `check_a2a_sdk.py` 并改协议层）
- 把"没测过的数字"写进 README / REPORT
- 为了让结果好看而改评测口径、删失败样本、调阈值
- kill 不属于本项目的进程
- 在没跑回归的情况下提交（先跑 `05` 的三条基线）

## 二、阶段工作流（用户的明确要求）

```
1. 声明本阶段的验收标准（可执行、可判定）
        ↓
2. 实现 + 单测（零网络零容器）
        ↓
3. 真实验收（必须含真实链路，不能只跑单测）
        ↓
4. 更新 REPORT / README / handoff
        ↓
5. 汇报：通过项 / 未通过项 / 问题清单 / 建议
        ↓
6. ★ 停下来问用户"是否继续下一阶段" ★
```

**第 6 步不能省**。用户说过：
> "请在每个阶段完成后先进行验收……验收通过后，再询问我是否继续进入下一阶段，
> 得到我的确认后再开始下一阶段的工作。"

## 三、与用户协作的方式

### 用户偏好（从其历史要求提炼）

| 偏好 | 具体表现 |
|---|---|
| 要**结论**不要菜单 | "请基于你自身的判断做出推荐决策，不要仅罗列多个选项" |
| 计划内**直接做** | "请直接开始，无需额外说明或确认" |
| 要**可落地** | "确保结论可直接落地" |
| 要**讲因果** | 会追问"为什么这条命令会改变状态"，所以要解释机制而不只报结果 |
| 反感**空话** | 不要"建议采用 X"，要"改成 X，因为实测 Y" |

### 汇报风格（已形成的惯例）

- 先给**结论/数字**，再给**为什么**，最后给**边界**
- **主动暴露对自己不利的发现**（"这推翻了我上一轮的结论"）
- 被数据打脸时**直接承认并修正文档**，不粉饰
- 每个数字都指到"哪条命令能复现"

### 不要做的事

- 不要在没验证的情况下说"已完成"
- 不要把"跑通了"等同于"验收通过"（见 `08` 第 1 条）
- 不要在用户没问的情况下大改架构
- 不要用"显著提升""效果很好"这类没有区间的词

## 四、判断"该不该做"的四个问题

动手前自问：

1. **这改动会影响哪个已验收的数字？** 若影响，先跑基线、改完重跑、并记录变化原因。
2. **这个新功能有验收标准吗？** 说不出来就先别写。
3. **这个结论有区间吗？** 没有区间就只能说"方向性"，不能说"提升"。
4. **失败时会怎样？** 如果失败会伪装成"知识不足"（而不是报错），必须补测试。

## 五、如果发现方向可能有问题

比如你跑完阶段 7，发现"复杂题 +19pt"在扩样后不成立了。**正确做法**：

1. **如实写**：在 `REPORT.md` 里写"扩样到 50 条后，该差异区间 [−x, +y] 包含 0，原结论不成立"；
2. **更新 README** 里对应的表述（不要留着旧说法）；
3. **更新 `handoff/02`** 的"简历可用清单"，把这条移到"不能说"；
4. **在汇报里主动提出**，说明这对项目叙事的影响与替代方案。

**不要**：换个指标让结论好看、调样本让差异显著、或者沉默不提。

## 六、接手时的建议动作顺序

```
① 读 handoff/00 → 01 → 02（1 小时内）
② 跑三条基线命令（见 05），确认环境可用
③ 跑一次 ask 与前端，建立"它现在长什么样"的直觉
④ 读 03（架构）与 07（代码导览），对照代码看一遍关键路径
⑤ 读 04，确认下一阶段任务，写验收标准
⑥ 开始工作
```

## 七、联系方式/交接状态

- 项目的长期记忆在 `.workbuddy/memory/`，按日期记录每个阶段的决策与踩坑。
  想看"为什么这么做"，那里比文档更细。
- `REPORT.md` 是**数据的唯一权威**；`README.md` 是**对外门面**；本目录是**交接上下文**。
  三者若冲突，以 `REPORT.md` 为准，并修正另外两处。

## 八、最后一句话

这个项目最有价值的东西不是"用了多 Agent"，而是：

> **每个主张都有对照实验，每个数字都能一条命令复现，
> 每条站不住的结论都被标注了"站不住"。**

请保持这一点。它比多加一个功能珍贵得多。
