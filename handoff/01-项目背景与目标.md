# 01 · 项目背景与目标

## 一、用户的需求（原话摘录）

> "我计划开发一个用于写进简历的垂直领域多 agent 专家问答系统（法律合规场景）项目……
> 请你先阅读 `E:\AI大模型开发\A2A(陈杰)` 里的内容，将其作为多智能体项目的参考架构，
> 然后阅读 `E:\project\LawAnswer` 和 `E:\project\LawAnswer-doubao` 这两个法律领域 RAG 项目
> （均为我用 AI 生成），其中 **`E:\project\LawAnswer` 是我要写进简历的重点项目**。"

后续追加的关键要求：

| 要求 | 含义（对交接者很重要） |
|---|---|
| "请基于你自身的判断做出推荐决策，不要仅罗列多个选项" | 用户要**结论**，不要菜单。给方案要带理由与否决备选的理由 |
| "请直接开始，无需额外说明或确认" | 已授权的阶段内，别反复请示，直接做 |
| "请在每个阶段完成后先进行验收……得到我的确认后再开始下一阶段" | 阶段之间有**验收门**，不能连跑 |
| "确保结论可直接落地" | 不接受"建议采用 X"这种空话，要给出可执行步骤 |

**用户画像**：同时使用 macOS 与 Windows；偏好"先解释为什么，再执行"；会通过后续追问
理解每步命令带来的状态变化。因此**解释要讲清因果，不要只报结果**。

## 二、为什么是"法律 + 多 Agent"

这不是随便组合。三个参考项目各自暴露了一个缺口：

| 项目 | 它擅长什么 | 它缺什么 |
|---|---|---|
| **A2A（陈杰 / SmartVoyage）** | 多 Agent 协议、中心化编排、MCP 工具层、Task 状态机 | **没有质量指标**。它证明了"能协作"，没证明"协作更好" |
| **LawAnswer**（简历重点项目） | 真实检索质量（R@5 0.7405）、RAGAS 评测、压测、完整工程 | **没有校验**。引用命中率 81.8% 是人工统计，口径模糊、无复现、无漏报率；多跳召回只有 0.4792 |
| **LawAnswer-doubao** | `term_map.py`（口语→法言法语）、`followup.py`（追问端点） | 架构价值低，是前身版本 |

**于是本项目的定位**：拿 A2A 的**协作骨架**、LawAnswer 的**真实检索与语料**，
补上两者都缺的那一块 —— **可验证性**（引用必须逐条核实，错了要能自己发现），
并用**对照实验**证明架构选择不是过度设计。

一句话：**不是"又一个法律 RAG"，而是"给多 Agent 加上度量与校验"**。

## 三、三个参考项目的真实情况（交接者需要知道的底）

### 3.1 A2A（`E:\AI大模型开发\A2A(陈杰)`）

- 结构：`a2a项目基础代码/` 下有 `_01function_call` → `_02mcp` → `_03agents` → `_04a2a` 递进式教学代码；
  另有 `SmartVoyage-项目深度解析.md`（约 2,000 行）与 `电商选品AgentTeam-可执行方案.md`。
- 架构：五层 —— 接入（FastAPI :8080）/ 编排（ChatService）/ Agent（3 个 A2A 专家 :5005-5007）/
  工具（3 个 MCP 服务、13 个 tool）/ 数据（MySQL 9 表 + Milvus）。
- 技术栈：LangChain + `python-a2a` + 官方 `mcp` SDK + `langchain-mcp-adapters`。
- 协作方式：**中心化编排 + 单向派发**，专家之间不直接通信。
- **它自己文档里写明的 7 处缺陷**（本项目刻意规避的）：
  1. 用关键词判断任务状态；
  2. `run_in_executor` 套 `asyncio.run` 绕事件循环冲突（`python-a2a` 是 Flask 同步底座）；
  3. 每次请求重建 MCP 会话；
  4. `artifacts` 有的是 str 有的是 dict（无契约）；
  5. 记忆用全局单例；
  6. 只有单测，**没有质量指标**；
  7. 一次简单查询调用 3~4 次 LLM，无成本控制。
- **值得抄的**：`_should_skip_planning()`（7 行规则省一次 planning）、
  意图识别一次产出"意图+槽位+追问话术"、AgentCard 的 `examples` 当 router 的 few-shot。

### 3.2 LawAnswer（`E:\project\LawAnswer`，简历重点项目）

- 规模：`app/` 约 11,147 行，模块 `api / core / db / ingest / retrieval / generation / orchestration / eval`。
- 语料：1,465 条法条（劳动合同法 98 + 劳动法 107 + 民法典 1260），父子分块 → 2,935 块。
- 真实指标（来自它的 `REPORT.md`，本项目已交叉验证过条数与语料一致性）：
  - 检索：L1 纯稠密 R@5 **0.7405** / MRR 0.7324；L6 加权 RRF + 法域过滤 R@5 **0.7071** / MRR 0.6886
  - 多跳召回仅 **0.4792**
  - RAGAS faithfulness 0.5189 → **0.7075**（+18.9pt，靠"没依据就不写"的 Prompt 约束）
  - 压测 QPS **2.686**（GPU，较 CPU 高 8.9×），240/240 成功
  - 引用命中率 81.8%（**人工统计**，这是本项目要替换的部分）
- **它的核心取舍**：单进程、6 分支双源路由、**路由选的是"数据源"而不是"执行者"**。
  因此没有任务状态机 —— 一次请求流到底，做不了"补槽位再执行"。
- **它写好但没接的那一刀**：`retrieve_multi()`（并行分检 + 名次交错融合）未接主链路与评测。
- **可复用资产**：`app/ingest/*`（clean / normalize / structure / chunker）**零外部依赖**，
  本项目直接复制，一行未改。

### 3.3 LawAnswer-doubao（`E:\project\LawAnswer-doubao`）

- `app/rag/*` 单层平铺，约 3,375 行。架构价值低。
- 但两个文件值得保留：
  - `term_map.py`：口语 → 法言法语的**确定性映射**（"老板辞退我" → "用人单位解除劳动合同"）
  - `followup.py`：追问独立端点

## 四、本项目的设计取舍（三条有判断的地方）

### 取舍一：多 Agent 的必要性不在"拆服务"，在"三个职责本来不该由同一个 LLM 承担"

划分依据是**是否需要判断**，不是**是否含 LLM**：

| 专家 | 含 LLM | 为什么单独拆出来 |
|---|---|---|
| Statute（取证） | ❌ | 只交证据、不写结论，因此永不会编故事 |
| Calc（计算） | ❌ | 法律场景算错赔偿金是事故，不是"偶尔不准" |
| Compliance（审查） | ✅ | 需要理解制度文本的意图 |
| Verifier（校验） | 部分 | 对抗生成结果，必须与生成器分离 |

**自检标准**（业界判据）：工具集、上下文、产物类型是否不同？
检索交证据、计算交数字、审查交 issue list、校验交裁决 —— **产物全不同**，通过。
反之"文书起草"与 Synthesizer 产物高度重叠，因此**砍掉**。

### 取舍二：用官方 `a2a-sdk`，不自研兼容层

初版建议"自研 200 行 async 兼容层"，理由是参考项目遇到事件循环冲突。
核实后发现**该理由只对 `python-a2a` 成立**（Flask 同步底座，`handle_task` 被强制同步）。
官方 `a2a-sdk` 是 Starlette + async，核心接口本就是
`async def execute(self, context, event_queue)` —— 那个坑在官方 SDK 里不存在。

**但这个决定有个前提**：必须锁 `a2a-sdk==0.3.22`。
`1.3.0` 已改成 **protobuf** 且重构服务端 API，`A2AStarletteApplication` 根本不存在。
详见 `docs/adr/0001-a2a-sdk-version.md` 与 `06-技术约束与依赖.md`。

### 取舍三：五个校验闸，而不是"查一下条号存不存在"

只查存在性只能挡住编造。更危险的是**条号真实、引文也真实，但这句话不是这条法条的意思**。

| 闸 | 查什么 | 用 LLM |
|---|---|---|
| G1 | 条号是否真实存在于检索到的证据 | ❌ |
| G2 | 引文与原文是否逐字一致（允许"……"显式省略） | ❌ |
| G3 | `as_of` 时点该条是否有效 | ❌ |
| G4 | 该条是否**支撑这句话**（语义） | ✅ |
| G5 | 金额是否等于公式结果 | ❌ |

**5 道里 4 道零 LLM**。一句话原则：
**必须正确的部分全交给代码，模型只负责把已核实的事实写成中文。**
