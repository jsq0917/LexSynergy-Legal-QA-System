## 三、核心指标（这是可以对外说的部分）

### 3.1 检索（100 条法条集 / 40 条集两套并存）

| 配置 | R@5 | R@8 | MRR |
|---|---|---|---|
| BM25 | 0.4119 | 0.4833 | 0.4905 |
| BM25 + Query 扩展 | 0.5857 | 0.7119 | 0.6272 |
| **稠密 bge-m3**（默认） | **0.7381** | 0.7690 | **0.7476** |
| 稠密 + BM25 加权 RRF | 0.7167 | **0.7833** | 0.7057 |

> 上表为 40 条集的四组消融原始记录。100 条集上 A 档（单 Agent）R@5 **0.7465**。

**三个反直觉结论**（都能复现）：
1. 词项路单独不可行（0.41）—— 法律术语密集，但用户说生活语言。
2. Query 扩展对词项路 +17.4pt，但补不全。
3. **混合不一定更好**：等权 RRF 只有 0.5786（比纯稠密低 16pt），权重降到 0.3 才回到 0.7167。

### 3.2b 130 条集（2026-10-28 扩样，阶段 7）

区间不含 0 的差异：**C−B 引用命中 +6.3pt [+2.7,+10.5]**、C−A 引注可溯 +2.6pt [+1.1,+4.3]、
D−A R@5 +4.0pt [+1.3,+6.8]、**D−C 引用命中 −7.9pt [−15.4,−0.5]（可区分地更低）**。
C−A 引用命中 +4.5pt [−2.7,+11.5]、多跳+复杂合并 C−A +5.3pt [−3.2,+14.0] 均**跨 0**。

**两条旧结论被推翻（以 130 条为准）**：

1. **"复杂题 +19pt"不成立**：13 条上是 A 0.609 → C 0.622（+1.3pt，区间 [−0.160,+0.173]）。
   旧 +19pt 来自 8 条样本，补样后连方向都保不住。
2. **"D 用一半的钱买到统计上分不出来的质量"不成立**：D 的引用命中比 C 低 7.9pt，
   130 条上区间不含 0；能站住的表述是"更便宜，但引用质量确实更低"。

### 3.2d 支撑率（阶段 9，2026-10-28：独立 judge + 3 次重跑）

判官 `qwen3.8-27b`（与生成模型 `deepseek-v4.1-flash` **异构**），`temperature=0`，

### 3.3 金额：按类型的分布（最有说服力的证据）

| 类型 | A 通过 | 算法在语料里吗 |
|---|---|---|
| severance / illegal / double_wage | **15/15 全对** | ✅ 法条原文写了折算规则与"二倍" |
| notice / annual_leave / non_compete | **0/11 全错** | ❌ 常数不在语料里 |
| overtime | 2/4 | 部分（倍数在，21.75 天不在） |

→ 结论：**不是模型算不准，是知识在哪里的问题**。修法必然是确定性引擎。

## 四、诚实的边界（这些必须知道）

1. **多跳/复杂扩到 50 条后，"复杂题 +19pt"已作废**（13 条上只有 +1.3pt，区间跨 0）；
   多跳+复杂合并的 C−A（+5.3pt）也测不出来。**能站住的只有 C−B 的校验收益**。
   复杂题 n=13 仍不足，若要下"复杂题"的结论还得继续扩。
2. **支撑率可复现了，但只在当前判官下成立**（阶段 9）：`qwen3.8-27b` + `faith-v1.0` + `temperature=0`，
   130 条 × 4 配置重跑 3 次，最大漂移 0.0051，C 0.954 / D 0.947 / B 0.930 / A 0.925。
   旧口径（漂移 ±0.02）的排序已作废；**换判官或改 Prompt 必须重测**，判官正确率与配对区间仍未测。
3. **金额集覆盖不了"未知公式"**：引擎只认 8 类，遇到第 9 类（工伤、分段计算）会报缺槽位。这是评测盲区，不是优点。
4. **流式已上线（阶段 8）**：快速通道首字 P50 753ms / P95 798ms，撰稿首字 P50 612ms；
   但**全编排的请求级首字仍 ~3.4s**，瓶颈已从撰稿转到 LLM 分诊（P50 2.3s）。
   总时长没变（撰稿完成仍需 2.5~3.5s），改的是体感。
5. **G4 偏保守**：会把"复述用户事实/复述计算结果"误判为无依据（已通过注入权威背景修正，但口径仍需扩样验证）。
6. **`--no-llm` 不做事实抽取**：规则版 Triage 只做关键词路由，必须给全 `--facts`。

## 六、过程中抓到的真 bug（说明这套东西真的在拦）

这些 bug 都**不是设计出来的**，是跑起来才暴露的，且都补了回归测试：

1. **排序键把"特别法优先"放在相关度之前** → 民法典题 top1 常是劳动合同法，R@5 掉 10pt。
2. **G2 引文错位**：±120/40 窗口找"最近的引号"，密集引用段落抓到邻居条文，一次误报 8 条。
3. **法名简称假阳性 G1**："《劳动合同法》第四十一条"按字面拼 key 查不到。
4. **G5 误报中间量**："57.47 元/小时"被判编造。
5. **Triage 过度触发测算**：40 题里 15 题掉进"请提供月薪和起止日期"。
6. **子查询替换而非追加** → 丢召回（q23/q25/q33/q34）。
7. **规则分诊把 `other` 当兜底** → "竞业限制不给补偿金还受约束吗"被判无关，一句话打发。
8. **档位判定与槽位判定互相锁死** → 不算钱 → 走快速 → 永不抽槽 → 永远不算钱。
9. **请求级总闸是"假闸"**：只检查每步开始前，对正在飞的调用无能为力（8.0s vs 设定 2s）。
10. **CLI 路径漏了预热** → 冷启动 20s 被算进检索超时，首个问题答"检索超时"。
11. **检索失败被说成"没有相关资料"** → 把系统故障伪装成知识边界（法律系统最不该犯的错）。
12. **金标自己算错**（c25：2 年 9 个月，N 应为 3 不是 2.5）→ 被 `check_calc_gold` 抓出。
13. **`--reuse` 汇总丢样本**：扩到 130 条时复用旧原始输出，`done` 只收了本次新跑的 30 题，
   标题却写"130 条"——差 10pt 的假数字差点被写进报告。修成 `_ordered_cases` 并补了 5 条回归测试。
