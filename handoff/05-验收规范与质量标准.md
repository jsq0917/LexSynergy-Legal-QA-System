# 05 · 验收规范与质量标准

> 这个项目最贵的资产不是代码，是"**每个数字都能追到一条命令和一份原始输出**"。
> 本文件定义怎么做验收，以及哪些做法会让这个资产贬值。

## 一、阶段验收的固定模板

每个阶段开始前先写清这张表，结束时逐项填结果：

| # | 标准 | 判定方式（可执行） | 结果 |
|---|---|---|---|
| V1 | … | 跑哪条命令 / 读哪个字段 | ✅/❌ |
| V2 | … | | |

**硬性要求**：

1. **判定方式必须是命令或字段**，不能是"看起来对"。
2. **至少有一项是真实链路验收**，不能只跑单测。
3. 不通过就**如实写不通过**，不许改标准迁就结果。

## 二、五条通用质量标准

### 标准 1：可复现

任何对外数字都必须满足：

- 有一条命令能重跑；
- 有原始输出落盘（`eval/results/`）；
- 写清样本量、样本集名、生成时间。

**反例（不要做）**：报告里写"引用准确率 81.8%"但不说怎么统计的 —— 这是 LawAnswer 的老问题，
本项目就是为了替换它才做的。

### 标准 2：带区间

单点估计不够。当前做法：

- 单配置区间：题目级重采样 4,000 次，取 2.5%/97.5% 分位；
- **差异区间：对逐题差值重采样**（paired bootstrap，保持配对结构）。

**判定规则**：区间不含 0 才能说"可区分"。**不写"显著"**（样本量和分布假设撑不起 p 值语言）。

### 标准 3：诚实标注不可用项

现有先例：支撑率标 ⚠、`未过闸` 一列对 A 档不适用、"9 条样本时只能当定性结论"。

**新增指标时必须问自己**：这个数的漂移有多大？样本量够不够？

### 标准 4：失败要能定位

系统失败时必须能回答"哪个环节、为什么"。已有支撑：
`timings`（triage/dag/synth/verify）、`verdict.fails[]`（具体闸 + 引用）、`degraded`（原因枚举）。

### 标准 5：故障不能伪装成知识边界

**这是法律系统的红线**。检索失败必须说"这次没查到"，不能说"没有相关规定"。
有测试盯住：`test_retrieval_failure_is_not_reported_as_no_data`。

## 三、回归基线（每次改动后必跑）

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1

# 1) 单测：必须 245 passed / 2 skipped，且耗时 <15s（零网络）
python -m pytest -o addopts="" -q

# 2) 校验能力：必须 8/8、0 误报
python -m eval.seeded_defect

# 3) 金额金标：必须 30/30
python -m scripts.check_calc_gold
```

**三条必须同时通过**。任何一条退步都要先修，不能"先提交再说"。

## 四、改数字的规矩

改动 `README.md` / `REPORT.md` 里的指标之前：

1. 确认是**同一套样本、同一口径**（130 条 / 100 条 / 30 条 / 40 条不能混）；
2. 重跑对应命令，保存原始输出；
3. 更新时**同时更新样本量与日期**；
4. 若数字变化，在 `REPORT` 里写清"为什么变"（换样本集？改了实现？修了 bug？）。

**禁止**：把 40 条集的旧数字与新 100 条集的数字放在同一张表里比较。

## 五、测试写作规范

| 规则 | 原因 |
|---|---|
| 单测必须零网络、零容器、零模型加载 | 2 skipped 的 A2A 集成用例是唯一例外（需起服务） |
| 断言要盯"语义"不是"实现" | 例：`assert took < 5` 盯的是"真的截断了"，不是"调了 wait_for" |
| 修 bug 必须补回归测试 | 现有先例：引文错位、法名简称、假总闸、漏预热 |
| 测试注释写清"为什么会有这条" | 例：`test_slow_synth_is_actually_interrupted` 的 docstring 记录了 8.0s 退化的历史 |

## 六、验收的常见坑（都是我踩过的）

| 坑 | 教训 |
|---|---|
| **只跑单测就宣布完成** | 假总闸、漏预热、冷启动超时**全都躲过了单测** |
| **只看总分不看逐题** | 排序 key 的 bug 让 R@5 掉 10pt，只看均值看不出来 |
| **相信文档里的数字** | 有几次数字是上一版的，没同步 |
| **局部重跑后读报告** | 报告曾是整体覆写，`--set calc` 会让 `law` 段变空（已被 `merge_report` 修掉） |
| **`/tmp` 当备份目录** | Git Bash 的 `/tmp` 与 Windows Python 看到的不是同一处 |
| **金标以引擎为准自动覆盖** | 会掩盖引擎的错；`check_calc_gold` 明确禁止 |
